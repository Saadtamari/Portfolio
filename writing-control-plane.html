Mission control for 350 agents

Once 350+ agents run across 35+ apps, the first question stops being “is the model good?” It becomes: which agent is failing, what is it costing, and can I stop it without a deploy?

Saad Al-TamariFrom the work: Agent Control Panel · Feb–Aug 20263 min read
Agent opsObservabilityLLM cost

The Agent Control Panel was my answer at Decasonic: one login where every agent is observable, measurable and remotely controllable. It runs as a modular monolith, one Node process serving the API and the React app, with 9 tables and about 60 endpoints. No message broker, no worker fleet. The interesting decisions were about who it serves and what it refuses to hide.

Four people, four questions

A health score anyone can read

Every connected app reports heartbeats and runs. Each agent gets a status (running, idle, paused, stopped or error) and a rolling health score recomputed on every run and heartbeat. I kept the formula deliberately simple, so an operator can check it in their head.

Control without redeploying

Pause, resume, stop or restart an agent, swap its model, or push a new system prompt, while the target app keeps running. Commands travel as HMAC-SHA256-signed webhooks with exponential-backoff retry, and each one has a visible lifecycle so nobody wonders whether it landed.

Prompts are versioned assets with one-click rollback. Feedback folds straight into a new version through tags like [INSTRUCTION], [IMPROVEMENT], [BUG FIX] and [KEEP DOING], and an AI reviewer scores answers from 0 to 100 with a written reason.

The platform watches itself

The panel’s own AI features are modelled as eight real internal agents, so the platform’s LLM spend is tracked with exactly the same machinery as everyone else’s.

Prices that check their own sources

Cost tracking is only as good as the price table behind it, and model prices change. So pricing discovery follows a protocol that spends tokens only when it has to.

Small things that matter in production

  • A heartbeat can never silently un-pause an agent someone stopped.
  • Token usage is upserted atomically, so concurrent heartbeats can’t lose counts.
  • When a provider fails, the fallback chain answers and the UI shows an amber badge, so an operator is never misled about which model replied.
  • Prompt and feedback bodies are base64-encoded on the way in, because a production firewall kept reading legitimate prompt text as an attack.

You can’t improve agents you can’t see. Visibility first, then control, then cost.
